# Midterm-Build-a-Secure-Data-Transmission-App-with-Hashing-and-Encryption

The program uses two hardcoded accounts for authentication the administrator account uses the username admin with the password admin123, and the regular user account uses the username user with the password user123. Each account is also assigned a role that determines what the user is allowed to do I the application.
Confidentiality is provided through AES-256 encryption, which converts the original message into unreadable encrypted data. It is also supported through role based access control because only a user with the admin role is allowed to decrypt and verify messages. Integrity is supported by SHA-256 hashing. The program creates a hash of the original message and later creates another hash after the message is decrypted. If the two hashes match, the program displays “Integrity Verified,” showing that the message was not changed during the encryption and decryption process. 
Availability is demonstrated by allowing authenticated users to log in and access the applications security features when needed. The logout function also clears stored user and encryption information and returns the program to the login screen so another user can securely access the application.
Entropy is important because encryption depends on unpredictable random values. The program generates a secure 256-bit AES key using AESGCM.generate_key() and creates a new random 12-byte nonce with os.urandom(12) when encrypting a message. High entropy makes these values difficult for an attacker to predict.
Key generation provides the secret key used by AES-GCM to encrypt and decrypt the message. A securely generated key helps protect the original information from unauthorized access because someone without the correct key should not be able to decrypt the encrypted message.
